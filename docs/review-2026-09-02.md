## Lens 1 — Security

### Fixed (migration `0015_hardening.sql`)

| Finding | What it allowed | Fix |
|---|---|---|
| `apply_scan_event`/`rebuild_asset_projection` granted to `papa_app` | Any member forges asset state with **no event row** — the evidence model severed | Revoked (incl. PUBLIC); pipeline now SECURITY DEFINER, pinned search_path |

## Lens 2 — Data correctness

### Fixed

- **The settle-lag hole (critical):** `pull_changes` stamped sequence numbers
  at write time but rows appear at commit time — a device pulling between two
  out-of-order commits skipped a row *forever*, and the watermark made the
  loss invisible. Cursor now capped by a snapshot-xmin horizon + 3s lag;
  reproduced and pinned with a two-connection dblink test.
- **Projection race (critical):** no row lock meant a late-uploaded older
  event could clobber newer state. `FOR UPDATE` in both projection functions.
- **Unresolved tags:** scans on a not-yet-synced label never projected, even
  after binding. Trigger now resolves live bindings; `bind_tag` rebuilds;
  `unresolved_tag` alert raised and auto-resolved. Log stays append-only.
- **Evidence grading:** owner-confirmed all-assumed dispatches graded
  `strong`; assumed>scanned now caps at `weak` before the role check.
- **Correction validation:** corrections must target same-org, same-asset.
- **`whats_out` never retired rows**; `back` dispatches no longer require a
  "destination".
- **Client engine:** transient errors never park ops (backoff saturates,
  parking only on server refusal); poison ops isolated exactly (server-named
  client_seq, else bisection); same-asset ops in a session carry real
  dependsOn edges; session dedup keyed by (asset, event_type); retired tags
  get their own outcome; manifests respect `removed_at`; `subrented` is no
  longer coerced to `packed`.

### Open

- `has_more` can read true against the dispatches watermark (dispatches bump
  it but are never pulled). Cosmetic-ish; pre-existing.
- A long-open write transaction stalls cursor advancement org-wide —
  bounded to re-delivery, never loss.
- **Partitioning decision:** reviewed; recommendation is the receipts table
  (the doc's own), with two amendments — no retention pruning on receipts
  without field data on retry age, and deferred-trigger checks (not
  "unenforced") for the self-FKs; `alerts.event_id` FKs need the same
  treatment. Still deferred to phase 3+, correctly.

## Lens 4 — Product strategy (decisions for the owner)

The moat vs Rentman/Current RMS/Cheqroom: offline-first as architecture,
WhatsApp as the interface, the enforcement model (gate/money pass), and
PKR-per-business pricing. The build is consistent with it. The strategic
risk is sequencing: the plan validates with the real vendor at the point of
maximum sunk cost.

**Recommended, in order (none yet done):**

1. **Print one rack's labels this week.** Tag survival is the assumption the
   entire product dies on, and the test has a built-in month of latency —
   start the clock now.
2. **Real-device speed spike before auth:** a throwaway Capacitor build on a
   cheap Android to prove the <100ms scan feedback and 30-minute thermal
   budget. Cheapest available kill-shot test.
3. **Thermal-printer challan (ESC/POS over Bluetooth, ~Rs 5,000 hardware).**
   Resolves the gate-pass-vs-no-printers contradiction, restores the
   enforcement mechanism, and is a demo that sells itself. Not on any phase
   list; should be.
4. **One afternoon with the pilot vendor before Phase 2** — deposits,
   pencils, credential norms; bookings code is currently built on
   "no primary source" guesses.
5. **String table now, Urdu later** — every English string hard-coded today
   makes the Roman-Urdu decision more expensive per commit.
6. **Promote the "Prove it" tech alibi card into Phase 1** — the plan calls
   it the thing that makes techs scan voluntarily, then never schedules it.
7. WhatsApp Business API sender (digest + alerts) has weeks of non-code
   lead time (template approval) — start the clock early.
8. A minimal append-only udhaar ledger is the owner's first ask and needn't
   wait for full Phase-3 invoicing.

Adoption-cliff audit of the current UX: clean overall; torch-in-low-light
fixed this session; volume-button capture and the haptic/audio vocabulary
are Capacitor-era items that must be on that task list explicitly.
